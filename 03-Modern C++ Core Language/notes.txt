Lvalue and Rvalue
==================
Lvalue
-------
==>Definition:An lvalue is an object/expression that represents an object with a 
              stable identity — usually something you can refer to again using 
              name.
==>example:
	int x = 10;

    cout << x;  // use x
    x = 20;     // use x again
here x is an lvalue.
==>Think:Lvalue = "I have an object that I can refer to again."

Rvalue
-------
==>Definition:An rvalue is generally a temporary value/object that is used as a 
              result or during an operation and doesn't have the same persistent identity as a named variable.
==>example:
   ->int x = 10;// lvalue
     int y = x + 5; // rvalue
   
   ->foo(10);//10 is an rvalue.

==>Think:Rvalue = "I'm using this value temporarily."

Move and Copy
==================

Copy
----
==>Definition:Copying means creating a new, independent object containing the same 
              value/data as the original object.
==>Example
   ->int x = 10;
     int y = x;
     They are two separate objects{x=10 and y=10}.
==>Think:Copy = "Make another object with the same data."

Move
-----
==>Definition:Moving means transferring the resources/data that an object owns to 
              another object instead of making a full copy.

==>Example
   ->std::string a = "Hello";
     std::string b = std::move(a);

==>Conceptually:
   ->Before:
     a → "Hello"
     b → nothing
   ->After move:
     a → moved-from state
     b → "Hello"
==>Think:Move = "Transfer the resources instead of making a copy."

Wrapper Function
=================
Wrapper Function
----------------
==>Definition:A wrapper is a middleman function that calls another function.
==>example:
   void target(int x) {
    cout << x;
   }

   void wrapper(int x) {
    target(x);
   }
==>Flow:

    main()
     ↓
  wrapper()    ← middleman
     ↓
  target()     ← actual work
==>Remember:Wrapper = middleman that calls another function.

T&& / Forwarding Reference
--------------------------
  template<typename T>
  void wrapper(T&& arg) {
      // target(std::forward<T>(arg));
  }

==>Definition:When T is deduced in a template, T&& can accept both lvalues and 
              rvalues.
==>Examples:

    int x = 10;

    wrapper(x);     // lvalue
    wrapper(10);    // rvalue

    C++ automatically deduces T.

    wrapper(x)  → T = int&
    wrapper(10) → T = int

==>Remember:T&& = accept lvalue or rvalue.

std::forward<T>(arg)
--------------------
==>Definition:std::forward<T>(arg) passes the argument to the next function while 
              preserving whether it originally came as an lvalue or rvalue.
==>lvalue:       
          lvalue
            ↓
          wrapper
            ↓
          forward
            ↓
          lvalue
            ↓
          target

==>rvalue:
          rvalue
            ↓
          wrapper
            ↓
          forward
            ↓
          rvalue
            ↓
          target
          
==>Remember:std::forward<T>() = pass it onward in its original form

Rule of three
=============
==>design your class so it doesn't manage any raw resources directly at all —
   instead, compose it entirely out of types that already manage their own resources correctly (std::string, std::vector, std::unique_ptr, etc.). If you do this, the compiler-generated defaults for all five special member functions are already correct, and you don't write any of them yourself.
==>Don't make your class responsible for managing raw resources if an existing 
   RAII type can manage them for you.
==>IntArrayModern
      │
      ▼
 std::vector<int>
      │
      ▼
 manages heap memory
      │
      ├── allocation
      ├── deallocation
      ├── copying
      └── moving


==>Raw resource
      ↓
  You manually manage it
      ↓
  Rule of Five
      ↓
  write special members yourself

==>RAII/resource-managing type
  (std::vector, std::string, unique_ptr...)
      ↓
  It manages the resource
      ↓
  Your class contains that type
      ↓
  Rule of Zero
      ↓
  compiler-generated special members are enough
